# Мультиплеер

Рабочие копии: `multiplayer/game` и `multiplayer/server`, обе на ветке `codex/multiplayer`.

## Комната и интерфейс

- В комнате два места: Синие и Красные. Вошедший участник сначала становится зрителем. Имена не используются.
- Выбор стороны находится в плашках над полем. Свободное место показывает «Ожидаем игрока» и кнопку «Играть за синих» или «Играть за красных» вместо счётчиков фигур. Занятое — «Вы» либо «Живой человек» и обычный состав армии.
- Выбор стороны означает готовность. После выбора первого игрока на месте его кнопки появляется «Отменить выбор». Выбор второй стороны атомарно запускает партию и показывает поле. Отдельной кнопки готовности нет. Размер плашек сохраняется между состояниями. Правила и расстановка стандартные.
- Игрок видит свою армию снизу. У зрителя Красные снизу. Значки лучников направлены к противнику; цвет, координаты ходов и правила не меняются от ориентации.
- Правая панель содержит номер комнаты, ссылку с копированием, завершение после старта, выход и число игроков и зрителей. Дублирующих карточек команд и формы имени нет.
- «Вдвоём по ссылке» в меню старта создаёт комнату и открывает её. Приглашение открывает существующую комнату без ввода имени.

## Места и жизненный цикл

| Событие | Результат |
|---|---|
| Выход до старта | Своё место освобождается, готовность сбрасывается |
| Выход во время партии или потеря связи | Место сохраняется, пока комната существует |
| «Завершить игру» от любого игрока | Оба места свободны, готовность сброшена, поле скрыто; участники остаются зрителями |
| Отмена выбора до старта | Своё место освобождается |
| Победа по правилам | Ходы блокируются; места освобождаются только по кнопке завершения |
| Хотя бы одно место свободно непрерывно более 10 минут | Текущее состояние комнаты очищается |
| В комнате вообще никого нет | Текущее состояние комнаты очищается |
| Явный вход по старой ссылке после очистки | Чистая комната с прежними номером и ссылкой |

Отключившийся игрок продолжает занимать место. Поэтому срок свободного места не применяется к нему. Однако отсутствие всех участников, включая зрителей, очищает комнату даже при занятых местах. Заходы зрителей и сигналы присутствия не продлевают срок свободного места.

Опрос состояния не оживляет закрытую комнату. Для этого нужен новый вход по ссылке или явное действие повторного входа. Неизвестные ссылки не создают комнаты. Ревизии возрастают и после оживления: старые команды не могут изменить новую комнату.

Сигнал присутствия отправляется каждые 20 секунд. Срок присутствия — 120 секунд для видимой вкладки и 600 секунд для скрытой. Запоздалый сигнал не сокращает уже выданный срок. Полностью приостановленный браузер после этого срока считается отключённым. Это допуск на восстановление связи, а не таймер партии.

## Данные и API

Гостевой секрет создаётся Web Crypto и хранится транзакцией IndexedDB. Вкладки одного источника разделяют гостевую идентичность, но имеют отдельные идентификаторы присутствия. Сервер хранит SHA-256 секрета; он не входит в приглашение, публичные снимки и журнал партии.

- `POST /api/rooms` — создание.
- `POST /api/rooms/:id/join` — вход, включая оживление ранее созданной комнаты.
- `GET /api/rooms/:id` — снимок.
- `POST /api/rooms/:id/presence` — присутствие вкладки.
- `POST /api/rooms/:id/leave` — явный выход.
- `POST /api/rooms/:id/commands` — `seat`, `stand`, `move`, `finish`.

Команда содержит `commandId`, `expectedRevision`, `matchId`, `type` и `payload`. Повтор с тем же содержимым безопасен; конфликт возвращает актуальное состояние. Клиент не переносит конфликтный ход на новую позицию автоматически. Проверка прав и ходов, запись состояния, события и квитанции происходят на сервере атомарно.

Номер и ссылка хранятся отдельно от текущего состояния. Серверный архив сыгранных партий сохраняется после очистки; оживлённая комната не восстанавливает из него поле или игроков. Раннее завершение записывается как прерывание без победителя. Публичный API архива не позволяет изменять серверные онлайн-партии.

## Разработка

Из `multiplayer/server` запустите `npm run dev:multiplayer` и откройте `http://127.0.0.1:5188`. Нужен Node.js 22.13+ и установленные зависимости сервера. Статика берётся из соседнего `game/dist`, отдельная SQLite-база — `.room-data/development.sqlite`.

Для двух гостей используйте разные браузеры/профили либо локальные адреса `127.0.0.1:5188` и `localhost:5188`. Третий отдельный источник можно поднять командой `ROOM_PORT=5189 npm run dev:multiplayer`; он использует ту же локальную базу.

Проверки игры: `npm test`, `npm run build`. Проверки сервера: `npm run test:rooms`, `npm run test:archive`, `npm run typecheck`, `npm run build`. Исследовательские тесты игры используют материалы workspace через ссылку `multiplayer/outputs`.

Текущий движок закреплён в `shared-engine/0.1.83`; предыдущие версии `0.1.78` и `0.1.79` сохранены для уже начатых партий. Контрольные суммы проверяются перед сборкой. Уже применённые миграции не редактируются.

Просроченная комната очищается при обращении к ней. Вход по старой ссылке открывает чистую комнату с прежним номером. Фоновую очистку запускает GitHub Actions через защищённый POST `/api/internal/rooms/cleanup` каждые 5 минут; расписание — `.github/workflows/room-cleanup.yml`, секрет — `ROOM_CLEANUP_TOKEN` в Sites и GitHub Actions. Возможны задержки очереди GitHub. После 60 дней без активности публичного репозитория расписание нужно включить снова. Миграции комнат применены. Публикуемые страницы используют серверное API комнат, локальный `dist` — API на том же источнике.
